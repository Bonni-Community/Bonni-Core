Bonni Core v0.1.21 – Docker / Compose

PostgreSQL muss nicht vorinstalliert werden. Diese Compose-Datei startet die
Datenbank automatisch als eigenen Container und speichert ihre Daten dauerhaft
im Volume postgres_data. Bonni Core v0.1.21 benötigt derzeit PostgreSQL;
eine vorhandene MySQL-Datenbank kann noch nicht als Bonni-Datenbank dienen.

1. Auf GitHub Actions warten, bis der Auftrag vollständig grün ist.
2. Die YML für die Host-Architektur herunterladen: AMD64 (Intel/AMD) oder ARM64.
   Voraussetzung: Docker Engine mit Linux-Containern und Docker Compose v2
   oder eine Verwaltung, die Docker-Compose-Dateien unterstützt.
3. Die YML in einem dauerhaften Installationsordner ablegen. Bei einer grafischen
   Container-Verwaltung den YML-Inhalt als Compose-Anwendung importieren.
4. Die drei BITTE-Werte am Anfang der YML ersetzen.
   Datenbank-Kennwort: mindestens 24 zufällige Zeichen.
   MASTER_KEY: mindestens 43 zufällige Zeichen; sicher und dauerhaft aufbewahren.
   Admin-Kennwort: mindestens 16 Zeichen mit Groß-/Kleinbuchstaben, Zahl und
   Sonderzeichen (z. B. !). Kein Dollarzeichen verwenden.
5. Anwendung mit gleichbleibendem Projektnamen bonni-core starten, z. B. AMD64:
   docker compose -p bonni-core -f Bonni-Core-v0.1.21-AMD64.yml up -d
   Für ARM64 den Dateinamen auf Bonni-Core-v0.1.21-ARM64.yml ändern.
   Danach http://SERVER-IP:4000 öffnen; Benutzername: admin.
   Die Startprüfung kann mehrere Minuten dauern. Einrichtung und 2FA abschließen.

Diese YML startet den Einzelbetrieb mit Core und PostgreSQL. Der bestehende
Host-Stack mit externem Update-Runner, Proxy und automatischem Notbetrieb wird
weiterhin über runtime:start eingerichtet; er ist nicht Teil dieser Compose-YML.
Diese Vorlage ist für eine neue Installation. Keine bestehende Host-Installation
oder Datenbank einfach darauf umstellen. Versionswechsel brauchen Sicherung und
die zur Version passenden Datenbankmigrationen. Die YML allein migriert nicht.

Anwendungsname und Volumes bei Neustarts behalten. MASTER_KEY und Datenbank-
Kennwort nach Erstinstallation nicht ändern. Das Admin-Kennwort in der YML wird
nur für die erste Einrichtung verwendet; spätere Änderungen erfolgen in Bonni.
Ein erneutes Starten setzt ein bereits vorhandenes Admin-Kennwort nicht zurück.

GitHub liefert zusätzlich je Architektur eine echte Docker-TAR-Datei und deren
SHA-256-Prüfsumme. ZIP = signierte Bauquelle, TAR = importierbares Container-Image,
YML = Anwendungskonfiguration. Für den normalen Compose-Start genügt die YML plus
erreichbare Registry. In den von GitHub erzeugten YML-Dateien sind Bonni und
PostgreSQL an die Image-Digests der jeweiligen Architektur gebunden; sie wechseln
nicht unbemerkt auf eine andere Version.

Wenn ghcr.io Zugriff verweigert: mit docker login ghcr.io anmelden oder den
Registry-Zugang in der Container-Verwaltung hinterlegen. Alternativ das Paket
auf GitHub bewusst öffentlich
freigeben. Ein öffentliches Repository macht ein GHCR-Paket nicht automatisch
öffentlich. Der Ablauf ändert die Sichtbarkeit nicht.

Beim Import einer TAR die image-Zeile der passenden YML auf den im TAR enthaltenen
Tag bonni-core:0.1.21-amd64 bzw. -arm64 setzen.
PostgreSQL muss zusätzlich aus der Registry geladen werden; die TAR allein ist
kein vollständig netzunabhängiges Installationspaket.
